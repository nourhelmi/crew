# Handoffs

Both documents travel through `crew spawn --packet`; their level of delegated judgment
differs. Use only the fields that matter, not a mandatory form. Real safety, ownership
and user constraints remain binding at every level.

## Advisor mission

CoS (or another advisor delegating an outcome) describes what success means and which
decisions the receiving advisor owns. Leave diagnosis, design, decomposition, staffing,
implementation and repair strategy to that advisor.

Example:

> **Outcome:** Shop staff can receive stock and sell it without losing inventory accuracy.
>
> **Ownership and authority:** Own the inventory/POS outcome end to end. Choose how to
> solve and staff it. Use Sol for application building; you may manage Sol workers directly.
> Preserve the accepted money contract. CoS owns cross-mission priorities and integration.
>
> **Interfaces and dependencies:** Agree the transaction interface with the reporting
> advisor. Publish it before reporting integrates. Own your checkout from the supplied
> base; coordinate changes to shared interfaces with their owner.
>
> **Acceptance and return:** Demonstrate receiving, sale, retry and shortage behavior on
> the delivered revision. Return the branch/commit or other artifact locator, integration
> notes, evidence, decisions and unresolved dependencies in your assigned result.

A report mission returns a report, not an invented branch. Name dependencies and acceptance
without prescribing a worker sequence, launch count, exhaustive file list or tool recipe.
No routine CoS approval is needed for decisions already delegated.

## Worker execution packet

An advisor delegates a bounded implementation or review: goal or exact review target,
accepted decisions versus suggestions, edit surface and non-goals, relevant paths and
base revision, focused acceptance and proving checks, scratch/result locations and actual
stop conditions. Builders still diagnose and repair within scope. Checkers report the
as-found verdict separately from their own repairs and verify the affected delta.

Example: fix retry handling for the accepted transaction API in the POS client; preserve
the server contract, prove an ambiguous response cannot duplicate a sale, return the
commit and focused evidence. The advisor retains the complete inventory/POS outcome.
